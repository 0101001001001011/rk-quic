# rk_quic

QUIC и WebTransport для Dart поверх нативной библиотеки.

В Dart своего QUIC нет — оба запроса в трекере SDK закрыты со статусом «не
планируется», — поэтому реализация написана на Rust за границей C ABI и
достаётся через `dart:ffi`. Смысл всего этого в одном: **сервер получает право
заговорить первым.** Смена состояния задания печати, появившееся или отказавшее
устройство доходят до браузерного клиента в момент события, а не когда кто-то
в следующий раз спросит.

## Что умеет 0.1.0

Загружаться — на каждой платформе, где `dart:ffi` есть. И это всё, намеренно:
у пустой библиотеки нет своих причин упасть, поэтому красная сборка означает
неисправность конвейера и ничего кроме. Транспорт кладётся поверх уже
доказанного механизма, а не подмешивается в само доказательство.

```dart
import 'package:rk_quic/rk_quic.dart';

void main() {
  print(rkQuicVersion);       // 0.1.0 — прочитано из загруженной библиотеки
  print(hasNativeTransport);  // true, если она открылась и поколение ABI сошлось

  final probe = probeNativeLibrary();
  if (!probe.isUsable) {
    // Нет, не то поколение, не тот файл — или браузер. Исключения не будет.
    print(probe);
  }
}
```

`rkQuicVersion` в 0.0.1 был `const String`, теперь это `String?`. Ради этого
версия и поднята: константа продолжала бы сообщать верную версию, когда рядом
лежит библиотека годичной давности.

## Отказ — значение, а не исключение

Ничто здесь не бросает исключение из-за того, что нативной части нет, она
старая или ей плохо, и ничто не роняет процесс. Каждый исход — значение:

| `NativeLoadOutcome` | Что значит |
| --- | --- |
| `loaded` | пригодна, поколение ABI совпало |
| `unsupportedPlatform` | браузер: `dart:ffi` нет, и это навсегда |
| `libraryMissing` | ни под одним из пробуемых имён открыть нечего |
| `symbolMissing` | открылась, но не экспортирует ABI rk_quic |
| `abiMismatch` | работает и говорит на поколении, которого эта сборка не знает |

`abiMismatch` именно отвергается, а не используется осторожно: вызов через
поколение — это способ молча нарушить правила владения памятью, а всплывает он
падением без объяснений часом позже.

Статусы приходят из нативной части **по имени**, никогда по номеру: `"portInUse"`,
а не `4`. Незнакомое имя становится `RkQuicStatus.unrecognised`, а не чужой веткой.

## На каких платформах библиотека доезжает

| Платформа | Состояние |
| --- | --- |
| Windows | собрана и вызвана: `rk_quic.dll` рядом с runner |
| Linux | собрана и вызвана: `librk_quic.so` в `bundle/lib/` |
| Android | собрана и упакована: `librk_quic.so` в `lib/{armeabi-v7a,arm64-v8a,x86_64}` внутри APK |
| macOS, iOS | **написано, но не проверено сборкой** — Mac в распоряжении нет, см. `doc/native-build.md` |
| Web | нативной части нет по устройству: браузер — клиент этой точки, а не её хост |

Импортировать пакет из кода, который заодно собирается под web, безопасно:
`dart:ffi` спрятан за условным импортом, и в браузерной половине его нет.

## Кто что освобождает

В этой версии освобождать вызывающему нечего. Строка версии указывает в
статическую память библиотеки и живёт столько же, сколько процесс. Там, где
библиотека всё же выделяет память — подробность отказа, — буфер возвращается
через `rk_quic_string_free`, и Dart никогда не зовёт на него `free()` сам.
Правило одностороннее: **освобождает тот, кто выделил.**
